\begin{abstract}
  Sales agents on our CRM platform (uCall) currently fill in customer fields by hand after every call. This project presents a three-stage pipeline to automate that process: (1) Silero VAD removes silence and noise from the raw audio, (2) a wav2vec\,2.0 model transcribes the remaining speech in Vietnamese, and (3) a LoRA-fine-tuned LLM extracts structured CRM fields from the transcript. The pipeline will be evaluated on 13{,}232 real calls using Word Error Rate for ASR and Precision, Recall, F1 for the extraction stage.
\end{abstract}

\section{Introduction}

\textbf{uCall} is a \textbf{CRM and automation call system} built by my startup. One of its core features lets sales agents make calls directly from the web app, and while on the call they can view and update customer information in the same UI. Right now, after every call, agents have to \textbf{fill in those fields manually}, things like customer interest, callback date, budget, and so on. This is slow, and when agents handle dozens of calls a day, they often skip fields or enter inconsistent data.

The goal of this work is to \textbf{speed that up}: automatically extract customer information from the call audio and fill the CRM fields while the agent is still on the call. To do that, I propose a three-stage pipeline:
\begin{itemize}
  \item \textbf{Stage 1 -- Voice Activity Detection (VAD):} strip out silence and noise from the raw audio so only speech is kept.
  \item \textbf{Stage 2 -- Automatic Speech Recognition (ASR):} convert the speech into a Vietnamese text transcript.
  \item \textbf{Stage 3 -- LLM extraction:} a fine-tuned language model reads the transcript and outputs the structured fields that match the organisation's CRM configuration.
\end{itemize}
Section~2 covers the dataset and each pipeline stage. Section~3 describes the evaluation metrics.

\subsection{Why do we need to preprocess the audio?}
\textbf{The goal} is to feed a speech-to-text model \textbf{audio that is mostly speech}. Raw files add silence, hold tones, background noise, and non-speech events. That increases recognition errors. Preprocessing limits those segments before ASR.

Recordings are stereo: agent on the left channel and customer on the right in my setup. Downstream analysis targets the customer, so I take the right channel before VAD.

Voice activity detection (VAD) outputs time intervals with speech. I retain those intervals and drop the rest. That removes long silent regions and much background sound prior to ASR. It is an imperfect but standard front end.

\subsection{Pre-processing Step 2: Automatic Speech Recognition (ASR)}
After VAD segmentation, each speech-only chunk is forwarded to an Automatic Speech Recognition (ASR) model. The model converts audio segments into unstructured text transcripts. Segment transcripts are then merged by timestamp to reconstruct each full-call transcript.

Three ASR candidates are considered: wav2vec2 with a Vietnamese checkpoint \path{nguyenvulebinh/wav2vec2-base-vi}~\cite{nguyenvulebinh_wav2vec2_base_vi}, Whisper~\cite{whisper_repo}, and Zipformer~\cite{zipformer_hf,zipformer_paper}.

\subsection{Step 3: LLM Fine-Tuning}
In the final stage, reconstructed transcripts are turned into a supervised fine-tuning dataset for the downstream LLM.
What the model must predict is chosen by the customers's settings: it is fixed by a \textbf{system-level field configuration} (column names, types, allowed label sets, and output formats).
That configuration is the single source of truth for acceptable \texttt{response} values at training and deployment time.

Each row is a JSON object with \texttt{instruction}, \texttt{input}, and \texttt{response}.

\subsubsection{Model Selection \& Architecture}
Candidate model families are:
\begin{itemize}
  \item Qwen3.5 (\url{https://huggingface.co/collections/Qwen/qwen35})
  \item Gemma~4 E4B (\url{https://huggingface.co/google/gemma-4-E4B})
  \item SmolLM3 (\url{https://huggingface.co/blog/smollm3})
\end{itemize}
All are decoder-only Transformers built on self-attention~\cite{vaswani2017attention},
\[
  \mathrm{Attention}(Q,K,V)=\mathrm{softmax}({QK^{\top}}/{\sqrt{d_k}})\,V,
\]
which lets every token attend to the full transcript and resolve the implicit context needed for each structured field.
Among these candidates, smaller models are preferred: if extraction quality is comparable, a smaller architecture reduces inference and training cost

\subsubsection{Fine-Tuning Strategy \& Loss}
Because updating every parameter of a billion-scale model is expensive, the pipeline uses \textbf{LoRA}~\cite{hu2022lora}: the pre-trained weights $W_0$ are frozen and only a low-rank update $\Delta W = BA$ ($r\!\ll\!\min(d,k)$) is trained, cutting trainable parameters to a small fraction and further reducing GPU cost.
The training objective is the standard autoregressive \textbf{cross-entropy loss}, computed over response tokens only:
\begin{equation}
  \mathcal{L}
    = -\frac{1}{|\mathcal{R}|}
      \sum_{t \in \mathcal{R}}
        \log\, p_\theta\!\bigl(y_t \mid y_{<t}\bigr)
  \label{eq:ce_loss}
\end{equation}
where $\mathcal{R}$ is the set of response-token positions (instruction and input tokens are masked).
Minimising this loss teaches the model to assign high probability to the exact labels defined by the field configuration.

\section{Evaluation Metrics}
Because this proposed pipeline utilizes two distinct deep learning architectures to convert unstructured speech into structured CRM configurations, the evaluation strategy is split into \textbf{audio transcription evaluation} and \textbf{semantic extraction evaluation}.

\subsection{Automatic Speech Recognition (ASR) Evaluation}
To evaluate the performance of the \texttt{wav2vec2-base-vi} model, we utilize the \textbf{Word Error Rate} (WER).
WER is the standard metric for acoustic modelling~\cite{wikipedia_wer} as it measures the edit distance between the model's predicted transcript and the manual ground-truth transcript.
It is mathematically defined as:
\begin{equation}
  \mathrm{WER} = \frac{S + D + I}{N}
  \label{eq:wer}
\end{equation}
where $S$ represents the number of word \emph{substitutions}, $D$ represents \emph{deletions}, $I$ represents \emph{insertions}, and $N$ represents the total number of words in the reference transcript.

Minimising WER is important. Benchmarking has shown that \texttt{wav2vec2-base-vi} can achieve a WER of \textbf{6.53\%} on Vietnamese datasets~\cite{nguyenvulebinh_wav2vec2_base_vi}.
Minimising this acoustic error rate ensures that the downstream language model receives high-quality textual context.

\subsection{Contextual Extraction Evaluation (The LLM)}
To evaluate the Qwen model's ability to extract the correct customer-configured JSON fields (e.g., \texttt{Budget}, \texttt{Timeline}) from the transcribed text, I treat the task as a \textbf{token / entity classification} problem.
The system's performance will be measured using \textbf{Precision}, \textbf{Recall}, and the \textbf{F1-Score}.

For each target JSON field, the metrics are mathematically defined using True Positives~(TP), False Positives~(FP), and False Negatives~(FN):

\paragraph{Precision} evaluates how many of the fields the model extracted were actually correct.
\begin{equation}
  \mathrm{Precision} = \frac{\mathrm{TP}}{\mathrm{TP} + \mathrm{FP}}
  \label{eq:precision}
\end{equation}

\paragraph{Recall} evaluates how many of the actual true fields present in the customer's audio the model successfully caught.
\begin{equation}
  \mathrm{Recall} = \frac{\mathrm{TP}}{\mathrm{TP} + \mathrm{FN}}
  \label{eq:recall}
\end{equation}

\paragraph{F1-Score} is the mean of Precision and Recall.
\begin{equation}
  F_1 = 2 \times \frac{\mathrm{Precision} \times \mathrm{Recall}}{\mathrm{Precision} + \mathrm{Recall}}
  \label{eq:f1}
\end{equation}

\subsection{Notes on Metric Selection}
\begin{itemize}
    \item \emph{Accuracy} is misleading here because most of the transcript is ordinary conversation with no extractable data. A model that extracts nothing at all would still score $\sim$99\% Accuracy simply by ignoring rare targets~\cite{powers2020evaluationprecisionrecallfmeasure, jeni2013facing}.
    \item \emph{F1-Score} focuses only on the entities we care about: it drops when the model invents information that was never said (low precision) or overlooks something the customer actually mentioned (low recall)~\cite{powers2020evaluationprecisionrecallfmeasure}.
\end{itemize}
